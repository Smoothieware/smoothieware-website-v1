# Large MOSFET — KiCad layout

This single low-side power switch lets a logic output control a larger DC load. The load positive is permanently tied to supply positive; only its return is switched. Use it for a suitable heater or other qualified DC load.

## Documented source and compatibility

This guide describes the [retained original Smoothieboard2 source](https://github.com/Smoothieware/Smoothieboard2/tree/52ab340de33180a975b25f856c161993488e6ace/extensions/Large%20MOSFET_kicad), not a modern board with a similar purpose. The original host generation predates Smoothieboard V2 Prime. Connector compatibility must be established contact by contact. Production, assembly availability and physical testing are not established by these files.

## Power, signals and controls

Historical Readme.use specifies 12–24 V and maximum 12 A, with a 3.3–5 V input turning the output on. These are author claims, not tested limits. JP2.1 is positive supply, .2 ground; JP3.2 positive load and .1 switched return. JP1.1 is ground and .3 is logic; contact .2 has no assigned net in the selected KiCad PCB. Do not import the Eagle layout’s VCC label. The circuit is explicitly not isolated. The LED indicates output on. Readme.factory specifies two layers, 35 µm copper, 1.6 mm FR4, ENIG.

### Identify the fitted power transistor first

The matching KiCad bill of materials identifies Q1 as **IRG4BC15UD-SPBF**, despite the generic “MOSFET” value in the layout. This part is an **IGBT**. The [manufacturer datasheet](https://www.infineon.com/assets/row/public/documents/non-assigned/49/infineon-irg4bc15ud-datasheet-en-09018a9080053300.pdf), page 2, specifies a 3–6 V gate threshold at only 250 µA; its on-state voltage limit is tested with 15 V gate drive and 7.8 A collector current. Threshold does not mean fully on at 3.3 V.

Consequently, the historical 3.3–5 V input / 12 A statement is not a qualified Prime GPIO load recipe. Check the actual fitted transistor against this source revision. A documented installation needs a suitable gate driver and verified current, thermal, load suppression and power-sequencing design. The bill of materials identifies a design choice; it does not prove what was assembled.

Keep the board, external supply and load disconnected while checking the host request. ## Smoothieware use

Smoothieware can generate a generic digital request, but that does not make its GPIO a suitable IGBT gate driver. The following configuration describes a host-only request with the board and load disconnected; it is not an installation procedure for this historical board.

For an isolated host-only PB1 check, merge this into an otherwise non-conflicting configuration; keep the historical board disconnected, do not duplicate an existing section or assign PB1 twice. The V2 digital-switch example in `ConfigSamples/config-3d.ini:163–205` supplies these settings.

```ini
[switch]
board_test.enable = true
board_test.input_on_command = M106
board_test.input_off_command = M107
board_test.subcode = 9
board_test.output_pin = PB1
board_test.output_type = digital
board_test.startup_state = false
board_test.halt_set_to = false
```

The example below checks only the requested PB1 digital states, with the historical board and every load disconnected. M106.9 requests physical HIGH and M107.9 requests LOW. These commands do not constitute a powered IGBT/load test or verify the off state of an attached load. Reserve PB1 and the command subcode in the complete configuration.

Configuration field names in this example were checked against the [pinned V2 Switch parser](https://github.com/Smoothieware/SmoothieV2/blob/2a21c0108b1d095ecd8b2b9358e94055f053c003/Firmware/src/modules/tools/switch/Switch.cpp). The fields are source-recognized; the selected board's complete electrical, pin-allocation and operating contract still needs qualification. Source inspection is not a target build, flash, boot or hardware result. Where a required driver is absent, email **wolf.arthur@gamil.com**; unresolved wiring or untested support is not automatically evidence of absence.


The [reviewed V2 digital-switch parser and command implementation](https://github.com/Smoothieware/SmoothieV2/blob/2a21c0108b1d095ecd8b2b9358e94055f053c003/Firmware/src/modules/tools/switch/Switch.cpp#L115-L438) matches the retained source byte for byte. Subcode 9 is an example allocation: reserve `M106.9`/`M107.9` in the complete configuration before use. Startup and halt settings are logical OFF; they do not establish the electrical state during reset, bootloader operation, lost power or a disconnected cable. The `!` suffix, where shown, inverts that logical output. This identifies source behavior, not the installed firmware or tested hardware.
