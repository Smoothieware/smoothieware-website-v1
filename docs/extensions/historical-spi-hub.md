# SPI hub

This passive hub shares one SPI clock/data bus among four peripherals and gives each peripheral its own chip-select wire. It does not decode addresses or create extra independent SPI controllers. Typical use is several compatible SPI sensors on one bus.

## Documented source and compatibility

This guide describes the [retained original Smoothieboard2 source](https://github.com/Smoothieware/Smoothieboard2/tree/52ab340de33180a975b25f856c161993488e6ace/extensions/SPIHub), not a modern board with a similar purpose. The original host generation predates Smoothieboard V2 Prime. Connector compatibility must be established contact by contact. Production, assembly availability and physical testing are not established by these files.

## Power, signals and controls

P1 is upstream. Its contacts 7/8/9 are MOSI/MISO/SCK; contacts 3/4/5/6 are CS5/CS3/CS4/CS2. P2–P5 share bus and rails, with their own CS on contact 6. Contacts 3–5 on each downstream connector are separate unused nets. D1–D4 are status indicators whose drive paths require LED/resistor reconciliation. Do not connect two actively driven MISO outputs simultaneously.

### Annotated connector and component reference

These newly source-derived references retain the selected native outline, footprints, pads and graphics. They are not a recovered canonical abstract or a verified mating view. Read the connector sheets and net keys together: CS2–CS5 are separate source nets, and downstream contacts 3–5 retain their individual unassigned nets. GPIO/GPIO! are generic source symbol labels, not assigned firmware functions. Peripheral compatibility, MISO arbitration, powered-off release behavior, supply ratings and physical mating remain unqualified.

### Board reference

Use the overview to locate each connector, then open the function sheets for pin roles. These newly source-derived illustrations retain the selected board geometry; they do not establish Prime compatibility or cable orientation.

## Connect and try it

For two sensors, attach them to P2 and P3 and arrange independent CS2/CS3 control while sharing MOSI/MISO/SCK and ground. Match logic voltage, SPI mode, clock rate and inactive tri-state behavior. The hub’s older S-socket pinout must be mapped to a Prime hardware SPI port; GF’s arbitrary GPIO map is not a verified SPI peripheral mapping.
